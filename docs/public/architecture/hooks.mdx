# Plugin hooks

MemSmith observes a Claude Code session through command hooks. The hooks capture prompts and tool use, inject context, and enforce memory-first lookups. They never run generation. The MemSmith server turns captured events into observations.

`plugin/hooks/hooks.json` registers every hook. Except for `Setup`, each entry runs the same command:

```
node bun-runner.js server-service.cjs hook claude-code <handler>
```

`bun-runner.js` starts `server-service.cjs`, which reads the hook payload as JSON from stdin, runs the named handler, and writes the result to stdout. The handlers live in `src/cli/handlers/`.

## Registered hooks

| Event | Matcher | Handler | Timeout | Feature name |
|-------|---------|---------|---------|--------------|
| `Setup` | `*` | `version-check.js` | 300 s | None |
| `SessionStart` | `startup\|clear\|compact` | Starts the server, then `context` | 60 s each | `context` |
| `SessionStart` | `resume` | Starts the server only | 60 s | None |
| `UserPromptSubmit` | None | `session-init` | 60 s | `capture` |
| `UserPromptSubmit` | None | `prompt-injection` | 60 s | `prompt-injection` |
| `UserPromptSubmit` | None | `record-intent` | 60 s | `record-intent` |
| `PreToolUse` | `Read` | `file-context` | 60 s | `file-context` |
| `PreToolUse` | `Grep\|Glob\|WebSearch` | `discovery-gate` | 60 s | `discovery-context` |
| `PreToolUse` | `mcp__plugin_memsmith_mem__.*` | `tool-intent` | 60 s | `memory-first-gate` |
| `PreToolUse` | `Grep\|Glob\|Read\|Bash\|WebSearch` | `tool-intent` | 60 s | `memory-first-gate` |
| `PreToolUse` | `Task\|Agent` | `agent-directive` | 60 s | `subagent-directive` |
| `PreToolUse` | `mcp__plugin_memsmith_mem__observation_add` | `record-intent-intercept` | 60 s | `record-intent` |
| `PostToolUse` | `*` | `observation` | 120 s | `capture` |
| `Stop` | None | `answer-gate`, then `summarize` | 120 s | `answer-gate`, `summary` |

The plugin registers no `SessionEnd` hook. The `Stop` hook closes the session.

To turn off a hook feature for one session or for all sessions, use the feature names in the last column. For the syntax, see [Hook switches](/usage/hook-switches). To make a session record nothing while keeping search and the memory gates, see [Read-only mode](/usage/read-only-mode).

## Setup

The `Setup` hook runs `version-check.js` once per Claude Code launch. It reads the `.install-version` marker in the plugin folder and prints a hint to run `npx memsmith@latest install` when the marker is missing, unreadable, or older than the plugin. If the plugin folder has a `package.json` but no `node_modules`, it also runs `bun install --production` there, and removes a partial `node_modules` when that fails.

## SessionStart

On `startup`, `clear`, and `compact`, the first hook starts the MemSmith server. The `context` hook then injects, as `additionalContext`:

- The standing directives: the memory-first directive and the record-intent directive. A read-only session gets a read-only notice in place of the record-intent directive.
- A project notice, when the session created a project or uses a marker above its own folder.
- A link to the dashboard.
- The most recent observations of the project, headed "Latest context for orientation". The number comes from `MEMSMITH_CONTEXT_SESSION_COUNT` (default `10`, clamped to 1 through 50).
- Warnings, when the generation provider isn't ready, the server version differs from the plugin version, or a marketplace install needs setup.

When `MEMSMITH_TEAM_INJECT` is `true`, the hook also appends team memory from the server named by `MEMSMITH_TEAM_SERVER_URL`.

On `resume`, the hook starts the server and injects nothing.

## UserPromptSubmit

Three hooks run on every prompt.

**`session-init`** registers the prompt with the server:

- Skips projects that `MEMSMITH_EXCLUDED_PROJECTS` or `MEMSMITH_INCLUDED_PROJECTS` filter out, internal protocol payloads, and read-only sessions.
- Handles the `/incognito [on|off]` command, which stops capture for the session.
- Creates the project identity when the folder has none, and applies a pending Go Team join.
- Delivers events that the capture spool holds (see [Failure behavior](#failure-behavior)).
- Starts the server session through `POST /v1/sessions/start`.

**`prompt-injection`** handles questions about past work. For a prompt with a clear retrieval signal, it checks that memory is reachable, records the turn as a pending information request, and injects a directive to search memory. If memory holds fewer than `MEMSMITH_RETRIEVAL_MIN_HITS` results (default `1`), it also saves a `memory_gap` record. Every other prompt gets nothing. The hook does nothing when `MEMSMITH_SEMANTIC_INJECT` isn't `true` (default `true`). MemSmith doesn't inject memories into each prompt.

**`record-intent`** detects prompts that ask MemSmith to remember something. It arms `record-intent-intercept` for the turn. When `MEMSMITH_RECORD_INTENT_BACKSTOP` is `true` (default `true`), it also posts the prompt to `POST /v1/record-intent`, so the server writes the note even if the agent skips `note_add`.

## PreToolUse

**`file-context`** is the File Read Gate. It currently injects nothing. See [File Read Gate](/file-read-gate).

**`tool-intent`** is the memory-first gate. It always allows the memory tools and records that the topic of a search was consulted. For `observation_search`, `observation_get`, and `observation_context`, it also marks the turn's information request as answered. For `Grep`, `Glob`, a `Bash` command that starts with `grep`, `rg`, `ag`, or `find`, and `WebSearch`, it checks whether memory was consulted for that topic:

- In `hard` mode, it blocks the first call on a topic and tells the agent to search memory. Later calls on that topic pass.
- In `soft` mode, it adds a reminder and never blocks.
- When memory is unreachable, it allows the call and adds an "unavailable" notice.

`Read` calls pass through. The hook records them so a later re-read isn't treated as discovery. The gate skips all of this when `MEMSMITH_SEMANTIC_INJECT` isn't `true`.

**`discovery-gate`** is off by default. When `MEMSMITH_GATE_TOOLS` lists tools (or is `all`) and `MEMSMITH_TEAM_SERVER_URL` and `MEMSMITH_TEAM_API_KEY` are set, it queries team memory with the tool's search pattern and injects up to five matches. Only `Grep`, `Glob`, and `WebSearch` reach it, because of the matcher.

**`agent-directive`** adds the standing directives to the task of every subagent that the agent spawns, because subagents don't get a `SessionStart` hook. It never blocks the spawn.

**`record-intent-intercept`** rewrites an `observation_add` call during an armed record-intent turn so the record is saved as a user note.

## PostToolUse

`observation` sends each tool call to `POST /v1/events` as a `tool_use` event. It removes memory tags such as `<private>` and redacts known secret patterns first. It skips excluded projects, incognito sessions, and read-only sessions.

In team runtime, the hook also queues the event for generation on your machine, and the server records the event without generating.

## Stop

`answer-gate` runs first. In `hard` mode, if the turn's information request is still unanswered, it returns a block decision with the reason "Search memory (observation_search) before answering". The gate blocks at most once per turn. It doesn't block when `stop_hook_active` is set, in `soft` mode, for a subagent, when the request is older than 30 minutes, or when memory is unreachable.

`summarize` then runs in the same process. It records the last assistant message as an `assistant_message` event and ends the server session. It skips subagents.

For the full memory-first flow, see [Architecture overview](/architecture/overview#memory-first-answering).

## Failure behavior

Hooks fail open, so a MemSmith problem doesn't stop your work.

- **Unreachable server.** `observation` writes the event to `~/.memsmith/capture-spool.jsonl` (up to 5,000 events, oldest dropped first). The next `session-init` delivers the spooled events.
- **Transport errors.** The hook exits with code 0 and counts the failure. After `MEMSMITH_HOOK_FAIL_LOUD_THRESHOLD` consecutive failures (default `3`), the hook exits with code 2 and prints a warning that Claude Code shows to the model.
- **Unexpected errors.** The hook exits with code 2 and its message.
- **Gate errors.** The memory-first gate and `agent-directive` allow the tool call.

## Debug hooks

- Read the logs in `~/.memsmith/logs/memsmith-YYYY-MM-DD.log`.
- Run `memsmith doctor` to check your setup, including the generation provider, the access setting, and turned-off hook features.
- Run `npx memsmith enforcement status` to see the enforcement mode and where it comes from.
