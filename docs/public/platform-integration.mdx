# Platform integration

An agent platform connects to MemSmith in one or more of three ways:

| Path | Use it to | Examples |
|------|-----------|----------|
| Hooks | Capture prompts and tool use, and inject context automatically | Claude Code, Cursor, Windsurf, Antigravity CLI |
| MCP server | Let the agent search memory and save notes on request | Every platform, and Claude Desktop |
| HTTP API | Send events and read memory from your own code | Custom integrations |

All three talk to the same server. In the local runtime, the server listens at `http://127.0.0.1:<38877 + your user ID % 100>`. Run `memsmith status` to see the address. In the `server` runtime, the address is the team server that you configured.

## Hooks

A platform hook runs this command and passes the platform's hook payload on stdin:

```text
bun <plugin>/scripts/server-service.cjs hook <platform> <event>
```

The `<platform>` value selects an adapter in `src/cli/adapters/`. The adapter converts the platform payload into a normalized input and formats the handler result back into the shape that the platform expects. The `<event>` value selects a handler in `src/cli/handlers/`:

| Event | Purpose |
|-------|---------|
| `context` | Injects recent memory at session start. |
| `session-init` | Registers the session and the user prompt. |
| `observation` | Records a tool call or agent response. |
| `summarize` | Records a session summary. |
| `file-edit` | Records a file edit. |
| `file-context` | Adds file history before a read. |
| `prompt-injection`, `tool-intent`, `discovery-gate`, `agent-directive`, `record-intent`, `record-intent-intercept`, `answer-gate` | Retrieval and enforcement behavior. Claude Code uses these. |

Adapters exist for `claude-code`, `codex`, `cursor`, `windsurf`, and `antigravity-cli`. An unknown platform name uses the `raw` adapter.

To add a platform:

1. Add an adapter in `src/cli/adapters/` that implements `normalizeInput` and `formatOutput`, and register it in `src/cli/adapters/index.ts`.
2. Add an installer in `src/services/integrations/` that writes the platform's hook configuration. Each hook runs the command above with the platform name and an event.
3. Add the platform to `src/npx-cli/commands/ide-detection.ts` and to the `install` command in `src/npx-cli/commands/install.ts`, so that `npx memsmith install --ide <id>` works.
4. Add a test for the adapter under `tests/`.

For the shipped installers, see `CursorHooksInstaller.ts` and `AntigravityCliHooksInstaller.ts` in `src/services/integrations/`. For the Claude Code hooks, see `plugin/hooks/hooks.json`.

## MCP server

The MCP server is `plugin/scripts/mcp-server.cjs`. Register it in the platform's MCP configuration with `node` as the command and the script path as the argument. For an example, see [Claude Desktop MCP](/usage/claude-desktop).

It exposes `observation_search`, `observation_get`, `observation_context`, `note_add`, `observation_add`, `observation_record_event`, `observation_generation_status`, `session_start_context`, `smart_search`, `smart_unfold`, and `smart_outline`.

## HTTP API

The server serves the dashboard at `/` and an authenticated JSON API under `/v1/`. `GET /healthz` and `GET /v1/info` return health and generation status.

### Authenticate

Send an API key in the `Authorization: Bearer <key>` header or the `X-Api-Key` header. To create, list, or revoke keys, run `npx memsmith server api-key create|list|revoke`. A key can be scoped to a project, and write endpoints need a key with write access.

### Endpoints

| Method and path | Description |
|-----------------|-------------|
| `POST /v1/sessions/start` | Starts a session, or returns the existing one for the same `externalSessionId`. |
| `GET /v1/sessions/:id` | Returns a session. |
| `POST /v1/sessions/:id/end` | Ends a session. |
| `POST /v1/events` | Records one event. Add `?generate=false` to skip observation generation and `?wait=true` to wait for the generation job. |
| `POST /v1/events/batch` | Records 1 to 500 events in one request. |
| `GET /v1/events/:id` | Returns an event. |
| `POST /v1/memories` | Stores an observation or note directly. |
| `POST /v1/search` | Searches observations. An empty `query` lists recent observations. |
| `POST /v1/observations/get` | Returns full records for up to 10 ids. |
| `POST /v1/context` | Returns the most relevant observations for a query. |
| `GET /v1/stream` | Streams new observations as server-sent events. |
| `GET /v1/jobs`, `GET /v1/jobs/:id` | Lists generation jobs and returns one job. |
| `GET /v1/projects` | Lists projects. |
| `GET /v1/settings`, `PATCH /v1/settings` | Reads and updates server settings. |

### Record an event

```bash
curl -X POST "$MEMSMITH_URL/v1/events" \
  -H "Authorization: Bearer $MEMSMITH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "projectId": "my-project",
    "sourceType": "api",
    "eventType": "tool_use",
    "occurredAtEpoch": 1767225600000,
    "payload": { "tool": "Bash", "command": "npm test" }
  }'
```

Required fields are `projectId`, `sourceType` (`hook`, `worker`, `provider`, `server`, or `api`), `eventType`, and `occurredAtEpoch` in milliseconds. Optional fields are `serverSessionId`, `platformSource`, `payload`, `contentSessionId`, and `memorySessionId`.

### Search memory

```bash
curl -X POST "$MEMSMITH_URL/v1/search" \
  -H "Authorization: Bearer $MEMSMITH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "projectId": "my-project", "query": "authentication", "limit": 10 }'
```

`limit` accepts up to 100. Optional filters are `platformSource`, `obsType`, `lifecycleState`, `userDirected`, and `actor`. If the API key has no project scope, `projectId` is required.

## Privacy

Content inside `<private>` tags isn't stored. For details, see [Private tags](/usage/private-tags). `POST /v1/memories` redacts detected secrets before it stores content.
