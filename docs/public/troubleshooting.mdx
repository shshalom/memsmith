# Troubleshooting

## Start with the doctor

`memsmith doctor` checks Bun, uv, the plugin install, and the server, and reports what's wrong:

```bash
memsmith doctor
```

To repair what it can, such as restarting a stopped server, clearing stale server state, or reinstalling plugin dependencies, run:

```bash
memsmith doctor --fix
```

Without a global install, prefix each command with `npx`, for example `npx memsmith doctor --fix`.

## Server issues

### The server isn't running

1. Run `memsmith status`. If it reports `Server is not running`, run `memsmith start`.
2. If the server doesn't start, run `memsmith doctor --fix`.
3. Check the latest log in `~/.memsmith/logs/memsmith-YYYY-MM-DD.log`.

### The server runs an old version after an upgrade

`memsmith doctor` reports a version mismatch when the running server is older than the installed plugin. Run `memsmith restart`.

### Port conflicts

The server listens on `127.0.0.1` at `38877 + (your user ID % 100)`. If another process holds that port, set `MEMSMITH_SERVER_URL` in `~/.memsmith/settings.json` to `http://127.0.0.1:<free-port>`, then run `memsmith restart`. The CLI and the hooks read the server address from this setting.

The local runtime's embedded Postgres uses port `55433`. MemSmith never switches to a random port: if another process holds `55433`, startup fails with an error. Stop that process, or set `MEMSMITH_LOCAL_PG_PORT` to a free port.

### Embedded Postgres is still running after `memsmith stop`

This is expected: `memsmith stop` leaves embedded Postgres running so the next start is fast. To stop it too, run `memsmith stop --all`.

## Capture and context issues

### Hooks don't fire

1. Start a new Claude Code session after you install or update.
2. Run `memsmith doctor` and confirm that the plugin install check passes.
3. If the Setup hook prints `run: npx memsmith repair`, run it. It installs missing runtime dependencies and refreshes the version marker.

### No observations appear

1. Run `memsmith status` and open the **Dashboard** address it prints.
2. Confirm that your generation provider is configured in `~/.memsmith/settings.json`. For Gemini or OpenRouter, the API key must be set. After you change settings, run `memsmith restart`.
3. Check the server log for provider errors, such as an invalid key or rate limiting.

### Context doesn't appear at session start

- Memory injection starts on your second session in a project. The first session seeds memory.
- Confirm that the project isn't excluded by `MEMSMITH_EXCLUDED_PROJECTS`, and that it matches `MEMSMITH_INCLUDED_PROJECTS` if you set that allowlist.
- Confirm that `MEMSMITH_CONTEXT_OBSERVATIONS` isn't `0`.

### Searches return no results

- Observations are generated in the background. A new session's work can take a moment to become searchable.
- Search is scoped to the current project. Confirm that you're in the project directory you expect.
- Open the dashboard to confirm that observations exist for the project.

### A tool call is blocked with a memory-first message

With `MEMSMITH_RETRIEVAL_ENFORCEMENT` set to `hard` (the default), MemSmith blocks some discovery tools until Claude consults memory on the topic. Claude can unblock itself by calling `observation_search`, `observation_get`, or `observation_context`. To inject memory without blocking, set `MEMSMITH_RETRIEVAL_ENFORCEMENT` to `soft`.

### Claude is sent back to search memory before it finishes an answer

In `hard` mode, when your prompt asks about past work and Claude answers without searching memory, the `Stop` hook sends Claude back once with the message "This was a request for information about past work. Search memory (observation_search) before answering". Claude searches and then answers. This happens at most once per prompt. To refer to something said earlier in the same conversation without a search, say so, for example "you just said" or "earlier in this chat". To turn the check off, run `npx memsmith enforcement off`.

### `memsmith enforcement status` shows a different mode than you expect

The status line shows the mode that the hooks use and where it comes from: `default`, `set in settings.json`, or `set by the MEMSMITH_RETRIEVAL_ENFORCEMENT environment variable`. The environment variable overrides `settings.json`. The command reads the environment of the shell you run it in, which can differ from the environment Claude Code started its hooks with.

## MCP tool issues

### Memory tools aren't available

1. Run `/mcp` in Claude Code and confirm that the MemSmith server is connected.
2. Start a new session after you install or update the plugin.
3. Run `memsmith doctor --fix`.

## Installation issues

### `npm install -g memsmith` didn't set anything up

The global npm install provides only the `memsmith` CLI. Run `memsmith install` to register the plugin hooks and set up the server.

### Bun or uv is missing

Run `npx memsmith repair`. It installs Bun and uv if they're missing and runs `bun install` in the plugin directory.

## Debugging

### Turn on verbose logging

Set `MEMSMITH_LOG_LEVEL` to `DEBUG` in `~/.memsmith/settings.json`, then run `memsmith restart`. Logs are in `~/.memsmith/logs/`.

### Check server health

`memsmith status` prints the server address. To query its health endpoint directly, run:

```bash
curl http://127.0.0.1:<port>/api/health
```

## Get help

If these steps don't solve the problem, [open an issue](https://github.com/shshalom/memsmith/issues) with:

- The output of `memsmith doctor`
- Your MemSmith version (`npx memsmith version`)
- The relevant lines from the server log, with any secrets removed
