# LiteLLM Gateway

MemSmith can send its generation requests through LiteLLM or any other gateway that exposes an OpenAI-compatible chat completions API. Use the `openrouter` provider and point its base URL at the gateway. The gateway then handles model routing, centralized keys, budgets, and logging.

<Warning>
Claude gateway generation isn't supported. The `claude` provider calls the Anthropic Messages API directly and needs an Anthropic API key (`ANTHROPIC_API_KEY` in `~/.memsmith/.env`). It ignores `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN`, so an Anthropic-compatible gateway or bridge can't stand in for it.
</Warning>

## Configure LiteLLM

Define the model name that MemSmith requests:

```yaml
# litellm-config.yaml
model_list:
  - model_name: memsmith-generation
    litellm_params:
      model: openai/gpt-4o-mini
      api_key: os.environ/OPENAI_API_KEY

litellm_settings:
  master_key: sk-litellm-local
```

Start LiteLLM:

```bash
OPENAI_API_KEY=sk-your-openai-key \
litellm --config litellm-config.yaml --host 127.0.0.1 --port 4000
```

## Configure MemSmith

Set these keys in `~/.memsmith/settings.json`:

```json
{
  "MEMSMITH_SERVER_PROVIDER": "openrouter",
  "MEMSMITH_SERVER_MODEL": "memsmith-generation",
  "MEMSMITH_OPENROUTER_BASE_URL": "http://127.0.0.1:4000/v1",
  "MEMSMITH_OPENROUTER_API_KEY": "sk-litellm-local"
}
```

- `MEMSMITH_SERVER_MODEL` must match a `model_name` in the LiteLLM config. MemSmith doesn't translate model names.
- `MEMSMITH_OPENROUTER_API_KEY` is the LiteLLM master key or a virtual key. MemSmith sends it as `Authorization: Bearer <key>`.

Then run `memsmith restart`. A provider chosen on the dashboard **Settings** tab overrides `MEMSMITH_SERVER_PROVIDER` in the file.

## Verify

Run `memsmith doctor`. The **Generation** check reports `openrouter · API key present`. Doctor doesn't call the gateway, so confirm that requests arrive in the LiteLLM logs after your next Claude Code session.
