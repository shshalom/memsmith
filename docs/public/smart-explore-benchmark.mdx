# Smart Explore benchmark

Smart Explore uses tree-sitter parsing to navigate code through three MCP tools: `smart_search`, `smart_outline`, and `smart_unfold`. This page reports a comparison against the standard Explore agent, which uses `Glob`, `Grep`, and `Read`.

<Warning>
These measurements are historical. The team ran them on the upstream codebase before the worker and SQLite runtime was retired, so several files and symbols named below, such as `worker-service.ts` and `DatabaseManager.initialize`, no longer exist. The team hasn't re-run the benchmark on the current code. Use the numbers to compare the approaches, not as a prediction for your project.
</Warning>

## Summary

| Metric | Smart Explore | Explore agent | Ratio |
|--------|:---:|:---:|:---:|
| Discovery across files (5 queries) | ~14,200 tokens | ~252,500 tokens | 17.8x |
| Targeted reads (5 symbols) | ~5,650 tokens | ~109,400 tokens | 19.4x |
| Search then read one function | ~4,500 tokens | ~51,500 tokens | 11.3x |

## Method

- **Codebase:** the `src/` directory, with 194 TypeScript files and 1,206 parsed symbols.
- **Model:** Claude Opus 4.6 for both approaches.
- **Measurement:** `total_tokens` from the Explore agent's response metadata, and the token count that Smart Explore reports for its folded view.
- **Control:** The team told the Explore agents not to use the `smart_*` tools. In an earlier round the agents used them on their own, which invalidated the comparison.

## Discovery

Smart Explore answered each query with one tool call: 10 ranked symbols with signatures and line numbers, and a folded view of each matching file. The Explore agent used 15 to 37 tool calls per query and returned a written report.

| Query | Smart Explore | Explore agent | Ratio |
|-------|:---:|:---:|:---:|
| session processing | ~4,391 | 51,659 | 11.8x |
| shutdown | ~3,852 | 51,523 | 13.4x |
| hook registration | ~1,930 | 51,688 | 26.8x |
| sqlite database | ~2,543 | 58,633 | 23.1x |
| worker-service outline | ~1,500 | 38,973 | 26.0x |

The ratio is highest for narrow queries, because the Explore agent reads whole files to find a few symbols.

## Targeted reads

| Symbol | Lines | Smart Unfold | Explore agent | Ratio |
|--------|:---:|:---:|:---:|:---:|
| `initializeSession` | 135 | ~1,800 | 27,816 | 15.5x |
| `performGracefulShutdown` | 48 | ~700 | 19,621 | 28.0x |
| `hookCommand` | 45 | ~650 | 18,680 | 28.7x |
| `DatabaseManager.initialize` | 27 | ~400 | 22,334 | 55.8x |
| `startSessionProcessor` | 158 | ~2,100 | 20,906 | 10.0x |

The ratio falls as the symbol grows, because more of the file is useful. For the longest symbol, the Explore agent truncated the function body. `smart_unfold` extracts by syntax node boundaries, so it returns the whole symbol.

## When to use each

| Task | Better choice |
|------|---------------|
| Find where a symbol is defined | `smart_search` |
| List the functions in a file | `smart_outline` |
| Read one function | `smart_unfold` |
| Explain how a feature works across files | Explore agent |
| Review design patterns or onboard to a codebase | Explore agent |

Start with Smart Explore for discovery and navigation. Use the Explore agent when you need a written explanation that spans several files.

## Tool cost reference

| Operation | Tokens in the benchmark |
|-----------|:---:|
| `smart_search` | 2,000 to 6,000 |
| `smart_outline` | 1,000 to 2,000 |
| `smart_unfold` | 400 to 2,100 |
| Explore agent, one function | 18,000 to 28,000 |
| Explore agent, cross-cutting question | 39,000 to 59,000 |
| `Read` of a full file | 8,000 to 15,000 or more |
