# Telemetry

MemSmith can send anonymous usage analytics to a PostHog project that you control.

## Off by default

**MemSmith ships without a telemetry key, so by default it sends nothing.** Every telemetry transport is a no-op until you set `MEMSMITH_TELEMETRY_KEY`, either as an environment variable or in `~/.memsmith/settings.json`:

```json
{
  "MEMSMITH_TELEMETRY_KEY": "phc_your_project_key"
}
```

Without a key:

- No events are sent, whatever your consent setting is.
- The installer doesn't ask for telemetry consent.
- `npx memsmith telemetry status` reports `disabled (no telemetry key configured)`.

To send to a self-hosted PostHog instance, also set the `MEMSMITH_TELEMETRY_HOST` environment variable. The default host is `https://us.i.posthog.com`.

## With a key

After you configure a key, telemetry is opt-out. When a key is configured, the installer asks once at the end of `npx memsmith install` and remembers your answer. It skips the prompt when `DO_NOT_TRACK` is set and in CI or non-interactive installs.

Events are anonymous. Each one is identified only by a random install UUID (`crypto.randomUUID()`, generated locally on first use), and every property passes a whitelist scrubber before it's sent. Any property that isn't on the whitelist is dropped.

## What is collected

MemSmith sends these events from the `npx memsmith` CLI:

| Event | When |
|---|---|
| `install_completed` | `npx memsmith install` finishes. |
| `install_failed` | `npx memsmith install` aborts. |
| `uninstall_completed` | `npx memsmith uninstall` finishes. |
| `hook_failed` | A hook fails with a blocking error, or hooks can't reach the server several times in a row. |

### Fields on every event

| Field | Example | Description |
|---|---|---|
| `distinct_id` | `7f3c…` (random UUID) | Anonymous install ID, not derived from you or your machine |
| `version` | `13.10.2` | MemSmith version |
| `os` | `darwin` | Operating system platform |
| `os_version` | `25.6.0` | OS kernel release |
| `is_wsl` | `false` | Whether MemSmith runs under Windows Subsystem for Linux |
| `arch` | `arm64` | CPU architecture |
| `runtime` | `node` | `bun` or `node` |
| `runtime_version` | `22.14.0` | Runtime version |
| `node_version` | `22.14.0` | Node.js version |
| `is_ci` | `false` | Whether MemSmith runs in CI |
| `locale` | `en-US` | Language tag |

### Install and uninstall fields

| Field | Event | Description |
|---|---|---|
| `ide` | `install_completed` | IDEs you chose, from the installer's list (for example, `claude-code,cursor`) |
| `provider` | `install_completed` | Generation provider: `claude`, `gemini`, `openrouter`, or `ollama` |
| `runtime_mode` | `install_completed` | `local` or `server` |
| `is_update` | `install_completed` | Whether the install replaced an existing one |
| `outcome` | `install_completed` | `ok`, or `partial` when an IDE setup failed |
| `duration_ms` | `install_completed` | How long the install took |
| `interactive` | `install_completed`, `install_failed` | Whether the installer ran in a terminal |
| `install_method` | `install_completed`, `install_failed` | `npm`, `bun`, `pnpm`, `yarn`, or `unknown` |
| `bun_version`, `uv_version` | `install_completed` | Tool versions detected during the install |
| `claude_code_version` | `install_completed`, `install_failed` | Claude Code version, if installed |
| `error_category` | `install_failed` | A MemSmith error category ID, never an error message |

Install and uninstall events also set the same platform fields on an anonymous PostHog profile keyed to the install UUID, so that retention can be counted. The profile contains nothing beyond the whitelisted fields.

### Hook failure fields

| Field | Description |
|---|---|
| `hook_type` | `context`, `session-init`, `observation`, `summarize`, or `file-context` |
| `error_mode` | `worker_unavailable` (hooks can't reach the server) or `blocking_error` |
| `consecutive_failures` | Failures in a row when the threshold was reached |
| `threshold_tripped` | Whether the failure threshold was reached |

PostHog derives coarse location (country, region, and city) from the request IP at ingest. MemSmith never attaches the IP to an event.

## What is never collected

| Never collected | Notes |
|---|---|
| Prompts or conversation content | Not even truncated or hashed |
| File paths or directory names | |
| Source code | |
| Project or repository names | Including git remotes and branch names |
| Search queries | |
| Error messages and stack traces | Only a closed error category or mode |
| IP addresses | Never attached to events |
| Hardware or machine identifiers | Not even hashed MAC addresses or hostnames |
| Environment variable values | |
| Emails, usernames, or other personal data | |

Every field is a number, a boolean, a version string, or a value from a closed set that MemSmith defines. No field can carry free-form content.

## How to opt out

If no telemetry key is configured, telemetry is off and nothing else applies. With a key, any one of the following keeps telemetry off. MemSmith checks them in this order, and the first match wins:

1. **`DO_NOT_TRACK`**: Set `DO_NOT_TRACK=1` to force telemetry off. It overrides everything else.
2. **`MEMSMITH_TELEMETRY=0`** (also `false` or `off`): An environment override. `MEMSMITH_TELEMETRY=1` forces telemetry on.
3. **The config file**: `enabled: false` in `telemetry.json`.
4. **The CLI**:
   ```bash
   npx memsmith telemetry disable
   ```

To check the current state and which setting decided it, run:

```bash
npx memsmith telemetry status
```

## Debug mode

To see exactly what would be sent, set:

```bash
MEMSMITH_TELEMETRY_DEBUG=1
```

With debug mode on (and telemetry enabled), MemSmith prints each event payload to stderr and sends nothing over the network.

## Where the config lives

Consent and the anonymous install ID are stored in `telemetry.json` in the MemSmith data directory:

- Default: `~/.memsmith/telemetry.json`
- `$MEMSMITH_DATA_DIR/telemetry.json` if you've changed the data directory

```json
{
  "enabled": false,
  "installId": "<random UUID>",
  "decidedAt": "2026-06-09T21:00:00.000Z"
}
```

The `enabled` field is present only after you make an explicit choice: at the installer prompt, or with `telemetry enable` or `telemetry disable`. A file with only an `installId` means no decision was recorded, so the default applies: on when a key is configured, off otherwise. To reset completely, delete the file. A new install ID is generated on next use.
