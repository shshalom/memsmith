# Installation

## Quick start

### Option 1: npx (recommended)

To install and configure MemSmith, run:

```bash
npx memsmith install
```

The interactive installer does the following:

- Checks the runtime and installs Bun and uv if they're missing.
- Detects your IDEs (Claude Code, Cursor, Windsurf, OpenCode, Codex CLI, Antigravity CLI, and others) and lets you choose which ones to set up.
- Asks for a generation provider. Claude Haiku 5.5 is listed first and recommended. It needs an Anthropic API key, which the installer asks for; a Claude subscription login doesn't cover it. Gemini, OpenRouter, and Ollama are also available.
- After you choose Claude Haiku 5.5, asks "Install a local backup for outages? (8 GB)" with Yes preselected. For non-interactive installs, pass `--local-backup`.
- If you choose Ollama or the local backup, checks that Ollama is installed, running, and has the model (`gemma4:12b`, 8 GB download). With your consent, it installs Ollama (Homebrew on macOS, the official script on Linux), starts it, and downloads the model. On Windows and on macOS without Homebrew, it prints the install steps instead.
- Copies the plugin files into the Claude Code marketplace directory and registers the plugin.
- Starts the local MemSmith server.

### Option 2: Plugin marketplace

To install from the plugin marketplace inside Claude Code, run:

```bash
/plugin marketplace add shshalom/memsmith
/plugin install memsmith@shshalom
```

Restart Claude Code. A marketplace install copies the plugin but skips the installer, so MemSmith finishes the setup itself:

1. At the start of the first session, MemSmith installs Bun if it's missing, using Bun's official installer (into `~/.bun`, no `sudo`). If that fails, it tells you how to install Bun and waits a day before trying again. To skip the automatic install, set `MEMSMITH_SKIP_BUN_INSTALL=1`.
2. Once Bun is ready, usually in that session or the next one, Claude asks which generation provider to use and whether to set up Ollama, then runs `npx memsmith install` with your answers. For Claude, Gemini, or OpenRouter, Claude asks you to add the API key in your own terminal; it never asks for the key in chat.

To do the setup yourself instead, run `npx memsmith install`.

<Note>
`npm install -g memsmith` installs the `memsmith` CLI only. To register the plugin hooks and set up the server, run `memsmith install`.
</Note>

## Non-interactive options

| Option | Description |
|--------|-------------|
| `--ide <id>` | Sets up one IDE. IDs: `claude-code`, `cursor`, `opencode`, `windsurf`, `codex-cli`, `copilot-cli`, `antigravity`, `goose`, `roo-code`, `warp`. |
| `--provider <name>` | Sets the generation provider without the prompt: `ollama` (the default), `claude`, `gemini`, or `openrouter`. For Ollama, the installer only checks it and prints the fix commands; it doesn't install or download anything. |
| `--model <id>` | Sets the generation model for the chosen provider. |
| `--setup-ollama` | Installs Ollama, starts it, and downloads the model without asking. On Linux without a terminal, the installer prints the install command instead of running it, because the script can prompt for `sudo`. |
| `--runtime local\|server` | Selects the runtime. `local` (the default) runs an embedded Postgres; `server` connects to a team's MemSmith server. Add `--server-url <url>` for the server address. |
| `--no-auto-start` | Skips starting the server at the end of the install. This option is unrelated to starting at login. |
| `--start-at-login` | Registers MemSmith to start when you log in, without the prompt. Without this option, a non-interactive install registers nothing. |
| `--no-start-at-login` | Skips the start-at-login prompt and registers nothing. |

## Start at login

An interactive install on the local runtime asks `Start MemSmith when you log in?` and preselects **Yes**. The installer doesn't ask in CI or on the server runtime. If you register MemSmith, the login entry runs the MemSmith server `start` command once at login. That command starts the embedded Postgres and the server, then exits. MemSmith doesn't supervise or restart the server afterward.

To manage the login entry yourself, run:

```bash
memsmith autostart enable
memsmith autostart disable
memsmith autostart status
```

`enable` is idempotent. `disable` succeeds when nothing is registered. `status` shows whether the entry is registered and whether the script it runs still exists. It exits with code 1 when the entry is registered but broken.

| Platform | Login entry |
|----------|-------------|
| macOS | LaunchAgent at `~/Library/LaunchAgents/com.memsmith.start.plist`. Output goes to `~/.memsmith/logs/launchd-start.log`. Enabling it also starts MemSmith right away. |
| Linux (experimental) | systemd user unit at `~/.config/systemd/user/memsmith.service`. The server runs inside your user session and stops when your last session ends. If you turn on lingering with `loginctl enable-linger`, the server starts at boot instead. |
| Windows (experimental) | `MemSmith` value under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. You don't need administrator rights. A console window can appear at login. |

Only macOS has been verified on a real machine. Linux and Windows support is experimental.

On Linux without a working `systemctl --user`, such as a system without systemd or WSL, `memsmith autostart enable` fails and suggests that you add `memsmith start` to your shell profile.

If registration fails during an install or update, the install or update still succeeds. MemSmith shows a warning with the fix, `memsmith autostart enable`. `memsmith update` offers to register MemSmith once, in an interactive terminal on the local runtime, when nothing is registered.

## System requirements

- **Node.js** 20.12 or later
- **Bun** 1.0 or later (installed automatically if missing)
- **uv** (installed automatically if missing)
- **Claude Code** or another supported IDE

You don't need Docker. The local runtime downloads and runs an embedded Postgres.

## Runtimes

- **Local (default):** A single-user server with an embedded Postgres. Data lives in `~/.memsmith/pgdata`, and Postgres listens on `127.0.0.1:55433`.
- **Team:** Your hooks send observations to a shared MemSmith server backed by a remote Postgres. To set it up, run `npx memsmith install --runtime server --server-url <url>`.

The MemSmith server listens on `127.0.0.1`. Its default port is `38877 + (your user ID % 100)`, so accounts on a shared machine don't collide.

## Verify the installation

1. Run `memsmith status`. It shows whether the server is running, its address, and the dashboard URL.
2. Run `memsmith doctor` to check Bun, uv, the plugin install, and the server. To repair problems it finds, run `memsmith doctor --fix`.
3. Open the **Dashboard** address from `memsmith status`.

Without a global install, prefix each command with `npx`, for example `npx memsmith status`.

## Where data lives

MemSmith stores its state in `~/.memsmith/`:

- `pgdata/`: the embedded Postgres data directory (local runtime)
- `pg-binaries/`: downloaded Postgres binaries
- `logs/memsmith-YYYY-MM-DD.log`: server logs
- `settings.json`: your settings
- `telemetry.json`: your telemetry choice and anonymous install ID, if any

To use a different directory, set `MEMSMITH_DATA_DIR`.

## Build from source

```bash
git clone https://github.com/shshalom/memsmith.git
cd memsmith
npm install
npm run build
```

To run the tests, run `bun test`.

## Upgrade

To upgrade, run:

```bash
npx memsmith@latest update
```

The command does the following:

1. If a newer MemSmith is on npm than the CLI you ran, it reruns itself with that version.
2. It installs the new plugin into the Claude Code marketplace and cache folders, and moves every MemSmith plugin entry, user-wide and per-project, to the new version.
3. It restarts the local server on the new version and checks that the server reports it. A stopped server stays stopped, and a team server isn't touched.
4. If you installed the `memsmith` command globally with npm, it updates that command to the same version. If npm can't write to its global folder, the update still finishes and prints the `npm install -g` command to run yourself.

It keeps your settings and doesn't ask the installer questions again. When it finishes, restart Claude Code. `/reload-plugins` doesn't restart the running MemSmith MCP server, so new memory tools appear only after a restart.

| Option | What it does |
| --- | --- |
| `--force` | Reinstalls the plugin files even when they're current, or installs this CLI's version over a newer installed plugin. |
| `--no-self-update` | Uses the CLI you ran instead of checking npm for a newer one. |

If you update the plugin another way, for example with `claude plugin update`, the server keeps running the old version. MemSmith warns you about this at the start of the next session. To fix it, run `npx memsmith@latest update`.

If an update fails after it stopped the server, it tells you so. To retry the update and start the server again, run `npx memsmith@latest update --force`.

For the version history, see the [changelog](https://github.com/shshalom/memsmith/blob/main/CHANGELOG.md).

## Uninstall

```bash
npx memsmith uninstall
```

Uninstall also removes the start-at-login entry.

Close all Claude Code sessions first. Otherwise, active hooks can recreate `~/.memsmith`.
