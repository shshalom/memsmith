# Cursor integration

Every Cursor session starts without context: your agent doesn't remember what it worked on yesterday. With MemSmith, your agent builds knowledge about your codebase, decisions, and patterns over time.

<Info>
You don't need a Claude Code subscription. You can generate observations with Gemini, OpenRouter, or a local Ollama model instead of Claude.
</Info>

## How it works

MemSmith integrates with Cursor through Cursor hooks and an MCP server:

1. Hooks send prompts, shell commands, MCP tool calls, and file edits to the MemSmith server.
2. The server turns them into observations with your configured generation provider and stores them in Postgres.
3. MemSmith writes relevant history into a Cursor rules file so new chats start with context.
4. The MCP server lets the agent search memory with `observation_search` and `observation_context`.

## Prerequisites

- Cursor
- Node.js 20 or later. The installer installs Bun and uv if they're missing.

## Install

Run the installer with the Cursor IDE identifier:

```bash
npx memsmith install --ide cursor
```

The installer does the following:

- Installs the MemSmith plugin files and runtime dependencies.
- Writes user-level Cursor hooks to `~/.cursor/hooks.json`.
- Registers the MemSmith MCP server in `~/.cursor/mcp.json`.
- Starts the local MemSmith server, unless you pass `--no-auto-start`.

To choose a generation provider without the interactive prompt, add `--provider`:

```bash
npx memsmith install --ide cursor --provider gemini
```

For provider setup, see [Gemini](/cursor/gemini-setup) or [OpenRouter](/cursor/openrouter-setup).

<Warning>
In MemSmith 13.10.x, the Cursor hook installer can fail with an error that a bundled script is missing. If you see it, check the [issue tracker](https://github.com/shshalom/memsmith/issues) for the fix.
</Warning>

## Manage the server

| Command | Description |
|---------|-------------|
| `memsmith start` | Starts the local server and waits until it's ready. |
| `memsmith stop` | Stops the server. Add `--all` to also stop embedded Postgres. |
| `memsmith restart` | Restarts the server, for example after you change settings. |
| `memsmith status` | Shows whether the server is running, its address, and the dashboard URL. |
| `memsmith doctor` | Checks the install. Add `--fix` to repair what it can. |

Without a global install, prefix each command with `npx`, for example `npx memsmith status`.

## Verify the installation

1. Run `memsmith status` and confirm that the server is running.
2. Open the **Dashboard** address that `memsmith status` prints.
3. Restart Cursor and start a chat. New observations appear in the dashboard as the agent works.

## Troubleshooting

### The server isn't running

Run `memsmith doctor --fix`. It restarts the server and clears stale state when needed. Server logs are in `~/.memsmith/logs/`.

### Hooks don't fire

1. Restart Cursor after installation.
2. Confirm that `~/.cursor/hooks.json` contains MemSmith hook entries.

### No context appears

1. Run `memsmith status` and confirm that the server is running.
2. Open the dashboard and confirm that observations exist for the project.
3. Confirm that your provider API key is set in `~/.memsmith/settings.json`.
