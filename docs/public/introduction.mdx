# MemSmith

**Persistent, local-first memory for Claude Code, with optional shared team memory.**

MemSmith captures what your agent does in each session, turns it into searchable observations, and makes them available in later sessions. Claude keeps its knowledge of a project after a session ends.

## Quick start

To install, run:

```bash
npx memsmith install
```

Or install from the plugin marketplace inside Claude Code:

```bash
/plugin marketplace add shshalom/memsmith
/plugin install memsmith@shshalom
```

Restart Claude Code. Session-start context appears from your second session in a project. For the steps, see [Installation](/installation) and [Getting started](/usage/getting-started).

## What MemSmith does

- **Captures** prompts, tool use, file edits, and session summaries through Claude Code hooks, and redacts known secrets before it stores anything.
- **Generates** observations from that activity with a provider that you choose: Claude, Gemini, OpenRouter, or Ollama.
- **Stores** observations in Postgres with pgvector, and ranks searches with keyword and semantic matching.
- **Recalls** memory through MCP tools, a CLI, and a dashboard. Claude searches memory before it searches the code or the web.
- **Shares** memory with a team through a team server, or stays on your machine with the local runtime.

For every capability and where it's documented, see the [capability overview](#capability-overview).

## How it works

```
Session start  → Inject recent observations for orientation
Tool use       → Hooks send activity to the MemSmith server
Generation     → Your provider turns activity into observations, stored in Postgres
Your question  → Claude searches memory with the memory tools, then checks the code
Claude stops   → The server summarizes the turn
```

**Core components:**

1. **Plugin hooks**: `Setup`, `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, and `Stop`. See [Hooks](/architecture/hooks).
2. **MemSmith server**: Listens on `127.0.0.1` at `38877 + (your user ID % 100)`. It stores observations, runs generation, and serves search, context, and the dashboard.
3. **Postgres with pgvector**: The local runtime runs an embedded Postgres in `~/.memsmith/pgdata`. The team runtime connects to a remote Postgres.
4. **Local embedder**: Computes embeddings on your machine, so semantic search needs no extra API key.
5. **MCP server**: Exposes the memory tools and the `smart_*` code exploration tools.

For details, see the [architecture overview](/architecture/overview).

## System requirements

- **Node.js** 20.12 or later
- **Bun** 1.0 or later (installed automatically if missing)
- **uv** (installed automatically if missing)
- **Claude Code** or another supported IDE (Cursor, Windsurf, OpenCode, Codex CLI, Antigravity CLI, and others)

You don't need Docker or a separate database for the local runtime.
