# Getting started with MemSmith

## How it works

After you install MemSmith, it works in the background:

1. **Start Claude Code.** The SessionStart hook injects recent observations and summaries for the project.
2. **Work as usual.** Hooks send each prompt and tool call to the MemSmith server.
3. **The server generates observations.** Your configured provider turns tool activity into observations, which the server stores in Postgres with embeddings for semantic search.
4. **Claude finishes responding.** The Stop hook asks the server to summarize the session.
5. **Your next prompt.** MemSmith injects the most relevant memory for that prompt.

Memory injection starts on your second session in a project. The first session seeds memory.

### What an observation contains

- **Title** and **subtitle**
- **Narrative**: what happened and why
- **Facts**: key learnings
- **Concepts**: tags used for search
- **Type**: for example, `bugfix`, `feature`, `decision`, or `discovery`
- **Files**: the files read or changed

### Session summaries

When Claude finishes responding, MemSmith records what you asked for, what Claude investigated and learned, what it completed, and the next steps.

### Context injection

At session start, MemSmith injects up to `MEMSMITH_CONTEXT_OBSERVATIONS` recent observations (default 50) across up to `MEMSMITH_CONTEXT_SESSION_COUNT` sessions (default 10), for orientation. After that, Claude searches memory itself whenever it needs information it doesn't have, before searching the code or the web. For details, see [Configuration](/configuration).

## Search your history

Ask Claude in plain language:

```
"What bugs did we fix last session?"
"How did we implement authentication?"
"Why did we choose this approach?"
```

Claude uses the MemSmith MCP tools: `observation_search` returns a ranked index of matching observations, and `observation_get` returns the full records for the ones that matter. You can also run `/ms-mem-search` to follow the search workflow explicitly.

To search from a terminal, run these commands from a project folder:

```bash
memsmith search "start at login"     # Ranked index of matching observations; add --limit <n> for up to 25
memsmith get <id> [<id>...]          # Full records for up to 10 ids from the index
```

The commands search the project that the current folder belongs to. In a git repository, they also work from any subfolder. To use another folder's project, set `MEMSMITH_PROJECT_CWD` to that folder.

`memsmith search` accepts these options anywhere on the line:

- `--actor <name>`: return only records written by that actor. With no query, it lists the actor's most recent records. For how actors are set, see [Actor tags](/configuration#actor-tags).
- `--limit <n>`: return up to `n` results. The default is 10 and the maximum is 25.
- `--json`: print JSON instead of text.

To search for text that starts with `--`, put `--` before it: `memsmith search -- --force flag`. Every word after `--` is part of the query.

### JSON output

With `--json`, the memory commands print one JSON object to stdout. `memsmith search --json` prints this shape:

```json
{
  "project": { "id": "proj-1", "folder": "/work/repo" },
  "query": "start at login",
  "actor": null,
  "results": [
    {
      "id": "obs-1",
      "date": "2026-11-05",
      "type": "decision",
      "title": "Start-at-login design",
      "snippet": "One-shot login entry with no supervision.",
      "actor": "reviewer",
      "actors": ["reviewer"],
      "supersededBy": null
    }
  ]
}
```

`actor` in a result is `null` when the record has no single actor, and `actors` is empty when it has none. `memsmith get --json` prints `project`, `results`, and `notFound`. Each result is the full record: `id`, `date`, `type`, `kind`, `lifecycleState`, `title`, `content`, `actor`, `actors`, `supersededBy`, `createdAtEpoch`, `updatedAtEpoch`, and `metadata`. `memsmith get` exits 1 when none of the ids exist.

When a command fails with `--json`, it prints the error to stdout and exits 1:

```json
{ "error": { "code": "server_unreachable", "message": "The MemSmith server is not reachable. Start it with: memsmith start" } }
```

The error codes are `usage`, `invalid_actor`, `no_project`, `read_only`, `server_unreachable`, `server_timeout`, `auth_failed`, and `request_failed`.

## Record a note

When you ask Claude to remember, record, or note something, it saves a user note with the `note_add` tool. Notes appear in the dashboard's notes panel and rank ahead of ambient observations in search.

To save a note from a terminal, run `memsmith note` from a project folder:

```bash
memsmith note "Deploys freeze on Fridays"
git log -1 --format=%B | memsmith note -    # Read the note from stdin
```

`memsmith note` saves the same kind of user note as `note_add`, for the project of the current folder or of `MEMSMITH_PROJECT_CWD`. It stamps the note with `MEMSMITH_ACTOR` when that is set. When `MEMSMITH_MODE` is `read`, it refuses and saves nothing. It exits 0 when the note is saved and 1 otherwise. With `--json`, it prints `{ "project": {...}, "note": { "id", "content", "actor", "createdAtEpoch" } }`.

## Open the dashboard

Run `memsmith status` and open the **Dashboard** address it prints. The dashboard shows your observations, notes, and generation status. You can also run `/ms-dashboard` inside Claude Code.

## Manage the server

The server starts automatically with your first session. These commands help with diagnostics:

```bash
memsmith status     # Show whether the server is running, its address, and the dashboard URL
memsmith start      # Start the server and wait until it's ready
memsmith stop       # Stop the server (add --all to also stop embedded Postgres)
memsmith restart    # Restart the server, for example after you change settings
memsmith doctor     # Check the install (add --fix to repair problems)
```

Without a global install, prefix each command with `npx`.

## Multi-prompt sessions and `/clear`

A session can span many prompts. When you run `/clear`, the session continues:

- MemSmith re-injects context from recent sessions. The SessionStart hook fires with `source: "clear"`.
- Observations are still captured for the current session.
- A summary is generated when Claude finishes responding.

## Keep content private

To keep content out of memory, wrap it in `<private>...</private>` tags. For details, see [Private tags](/usage/private-tags).
