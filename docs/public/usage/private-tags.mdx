# Private tags and secret redaction

MemSmith keeps sensitive content out of memory in two ways:

- **Private tags** remove text that you mark with `<private>` before MemSmith stores it.
- **Secret redaction** replaces known secret patterns automatically, with no tags.

Neither method changes the live conversation. Claude sees the full text, including the tags, during the session.

## Private tags

Wrap text in `<private>` tags to keep it out of memory:

```
<private>
Host: internal-db-prod.company.com
</private>

Why does this connection fail?
```

MemSmith stores the question but not the wrapped text.

### What MemSmith strips

MemSmith removes the tag, its attributes, and everything up to the closing tag. It strips these tags:

`private`, `memsmith-context`, `system_instruction`, `system-instruction`, `persisted-output`, and `system-reminder`.

MemSmith strips them from:

- Your prompts, before it saves them or uses them for recall.
- Tool inputs and tool responses, before it stores them as events.
- The last assistant message that MemSmith uses for a summary.
- The prompt that MemSmith sends to the generation provider. If every event in a batch is private, MemSmith skips generation for the batch.
- Generated observations, as a final check. MemSmith drops an observation that has no text left.

### Rules and limits

- A tag can span multiple lines, and you can use several tags in one message.
- A tag needs a closing tag. MemSmith keeps an unclosed `<private>` and the text after it.
- MemSmith ends a block at the first closing tag, so nested `<private>` tags aren't supported.
- Tag names are lowercase.
- No setting turns tag stripping off.

## Secret redaction

MemSmith replaces known secret patterns in captured content with a marker that names the kind of secret and keeps the surrounding text:

```
ANTHROPIC_API_KEY=[REDACTED:anthropic_key]
Authorization: Bearer [REDACTED:bearer_token]
postgres://app_user:[REDACTED:password]@db.internal:5432/app
{"db_password": "[REDACTED:password]"}
```

Redaction runs at several points:

- The hook redacts each event before it sends the event to the server or writes it to the local spool.
- The MCP tools redact before they write.
- The server redacts again before it stores an event or sends it to a generation provider, which covers events from an older hook or a third-party client.
- MemSmith redacts its own log lines in `~/.memsmith/logs`.

MemSmith recognizes these patterns:

- Provider keys and tokens: Anthropic (`sk-ant-`), OpenAI (`sk-`, `sk-proj-`), Stripe (`sk_live_`, `sk_test_`, `rk_live_`, `rk_test_`), GitHub (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`), GitLab (`glpat-`), Hugging Face (`hf_`), Google API keys (`AIza`), AWS access key IDs (`AKIA`, `ASIA`), Slack (`xoxb-`, `xoxp-`, and the other `xox` types), and npm (`npm_`).
- Bearer tokens, `Authorization` header values (`Bearer`, `Basic`, `token`, `Negotiate`), and JSON Web Tokens (JWTs).
- PEM and PGP private key blocks.
- Passwords in connection strings, such as `scheme://user:password@host`, `password` entries in `.netrc` files, and npm `_authToken` values.
- Values of names that end in `KEY`, `TOKEN`, `SECRET`, `PASSWORD`, or `PASSWD`, and `SECRET_KEY_BASE`. A name that ends in `PASS` counts when `PASS` is the whole name or follows `_`, `.`, or `-`, such as `SMTP_PASS`. A camelCase name such as `dbPass` counts when its value has at least 6 characters, including a digit or a symbol. MemSmith leaves graphics and build pass names, such as `renderPass`, alone. MemSmith redacts these in env form (`NAME=value`, `export NAME=value`), JSON (including escaped JSON), YAML, and command-line flags (`--api-key value`, `--password value`). It keeps the name and redacts only the value, including quoted passphrases that contain spaces.

To keep useful memory intact, MemSmith doesn't redact these values:

- Values that are too short or too plain to be a key, such as words without digits under a key or token name.
- Placeholders such as `<your-key>`, `xxx`, `${VAR}`, `$VAR`, and empty strings.
- Code references such as `process.env.API_KEY`, file paths such as `certs/server.key`, and type names such as `string`.
- Quoted text that names its own field, such as `"password": "Enter your password"`, and quoted labels. MemSmith treats a quoted value as a label when it has three or more words of plain letters and either starts with a capital letter or ends with `.`, `?`, `!`, or `:`. A passphrase of lowercase words with no closing punctuation, such as `correct horse battery staple`, or one with digits or symbols is still redacted. A passphrase in sentence case, such as `Correct horse battery staple`, isn't redacted.
- Names where the word is an identifier rather than a credential, such as a bare `key`, `idempotencyKey`, `PUBLIC_KEY`, `nextToken`, `pageToken`, and `max_tokens`.

Redaction is pattern-based, so MemSmith stores a secret in an unrecognized format as captured. Wrap such a secret in `<private>` tags. Redaction applies only to content that MemSmith captures after you update. Earlier memories, events, and log lines stay as they are.

## Choose between them

| Situation | Use |
|-----------|-----|
| A known key, token, or password format | Nothing. Redaction handles it. |
| A secret in an unrecognized format | `<private>` tags. |
| Text that isn't a secret but doesn't belong in memory | `<private>` tags. |

Use tags sparingly. Memory comes from what MemSmith captures, so heavy tagging reduces the context that future sessions receive.

To stop all capture for a session, see `MEMSMITH_ACCESS` and `MEMSMITH_HOOKS_DISABLED` in [Configuration](/configuration).
