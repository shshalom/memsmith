# Context engineering

Context engineering is the practice of choosing which tokens an agent sees on each turn: instructions, tools, retrieved data, and message history. The goal is the smallest set of high-signal tokens that produces the outcome you want. MemSmith applies these principles to agent memory.

This page summarizes Anthropic's article "Effective context engineering for AI agents" and maps each principle to MemSmith behavior.

## Why context size matters

A model's accuracy tends to fall as its context grows, so each token has a cost beyond its price. Treat context as a finite resource, and add a token only when it improves the next decision.

## Principles

### Write instructions at the right level of detail

An instruction that is too specific breaks on cases that its author didn't expect. An instruction that is too general gives the model nothing to act on. Write the smallest set of instructions that fully describes the behavior you expect, and add detail only when you observe a failure.

MemSmith applies this to its standing directive. The memory-first directive is a short, three-step flow: check the conversation, search memory, and validate against the code. It doesn't list every case.

### Keep tools few and distinct

If a human engineer can't say which tool fits a situation, an agent can't either. Give each tool one purpose, clear parameter names, and output that is no larger than it needs to be.

MemSmith applies this to its memory tools. `observation_search` returns a short index, `observation_get` returns full records, and `observation_context` returns the top matches in one call. Each tool caps its output.

### Retrieve just in time

Keep lightweight references, such as queries and file paths, and load data when the agent needs it. Pre-loading everything adds noise, and pre-loaded results can read as a finished answer that the agent doesn't check.

MemSmith injects only a short orientation at session start, and the agent fetches the rest with the memory tools. See [Progressive disclosure](/progressive-disclosure).

## Techniques for long tasks

| Technique | What it does | How MemSmith supports it |
|-----------|--------------|--------------------------|
| Compaction | Summarizes a conversation that nears its limit and continues from the summary. | The `SessionStart` hook runs again after `compact` and `clear`, so the agent gets the directive and recent context again. |
| Structured notes | Saves notes outside the context window and reads them later. | `note_add` saves a user note, and the observation pipeline saves what the agent does. Search finds both in later sessions. |
| Subagents | Gives a focused task to an agent with a clean context and takes back a short summary. | The `agent-directive` hook gives every subagent the same memory-first directive. |

## Choose an approach

| Situation | Approach |
|-----------|----------|
| The content is static and small | Load it up front. |
| The agent needs to explore | Retrieve just in time. |
| The conversation runs long | Compact it. |
| Work spans many sessions | Save notes and observations. |
| The task needs broad research | Delegate to subagents. |
