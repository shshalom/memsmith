# File Read Gate

The File Read Gate currently does nothing. MemSmith registers the hook, but the hook never blocks a `Read` call and never adds a file timeline.

## Current behavior

`plugin/hooks/hooks.json` registers the `file-context` handler as a `PreToolUse` hook with the `Read` matcher. The handler skips projects that `MEMSMITH_EXCLUDED_PROJECTS` or `MEMSMITH_INCLUDED_PROJECTS` filter out, and files smaller than 1,500 bytes. For every other file, it has no timeline to fetch, because the current server has no endpoint that returns observations by file path. The handler returns no context and the read proceeds.

The earlier gate depended on a worker route that the `local` and `server` runtimes don't include. Observations store the files they touched in their metadata, but search can't filter by file path yet.

## What to use instead

To read less of a file and keep the cost low, combine the memory tools with the code tools:

1. Search memory with `observation_search`, and fetch the records that matter with `observation_get`.
2. Get the structure of a file with `smart_outline`.
3. Read one function or class with `smart_unfold`.
4. Read the whole file only when the first three aren't enough.

For the reasoning behind this order, see [Progressive disclosure](/progressive-disclosure). For measurements of the code tools, see [Smart Explore benchmark](/smart-explore-benchmark).

The `Read` tool isn't part of the memory-first gate: `tool-intent` never blocks a `Read` call. See [Plugin hooks](/architecture/hooks).

## Turn off the hook

To skip the hook for a session, add `file-context` to `MEMSMITH_HOOKS_DISABLED`. For the syntax, see [Hook switches](/usage/hook-switches).
