# Modes & Languages

MemSmith uses a **mode system** to control what it records and which language it writes in. You can switch modes without reinstalling the plugin.

## What is a mode?

A mode is a configuration profile that defines the following:

1.  **Observer role**: How the model analyzes your work.
2.  **Observation types**: The categories an observation can have, such as bug fix or feature.
3.  **Concepts**: Semantic tags used for indexing, such as pattern or trade-off.
4.  **Language**: The language of generated observations and summaries.

## Configuration

To set the active mode, set `MEMSMITH_MODE` in `~/.memsmith/settings.json`:

```json
{
  "MEMSMITH_MODE": "code--es"
}
```

You can also set it as an environment variable:

```bash
export MEMSMITH_MODE="code--fr"
```

## Available Modes

### Code mode (default)
The standard mode for software development. It records bug fixes, features, refactors, and architectural decisions.

**ID:** `code`

### Code mode variants

Variants change how code mode behaves:

| Variant | Mode ID | Description |
|---------|---------|-------------|
| **Chill** | `code--chill` | Produces fewer observations. Records only work that is costly to rediscover, such as shipped features, architectural decisions, and non-obvious gotchas. Skips routine work and obvious changes. |

## Mode inheritance

A mode ID with the `--` separator inherits from its parent. For example, MemSmith resolves `code--es` as follows:
1.  Loads the `code` (parent) configuration.
2.  Loads the `code--es` (child) configuration.
3.  Merges the child into the parent. Child values take precedence.

A child mode changes only what it overrides, such as the language prompt, and keeps the parent's definitions.
