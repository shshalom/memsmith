# Development

This page describes how to build MemSmith from source, test a change, and submit it.

## Prerequisites

- Node.js 20.12 or later
- Bun 1.0 or later. Bun runs the test suite and the plugin scripts.
- Git

## Build from source

```bash
git clone https://github.com/shshalom/memsmith.git
cd memsmith
npm install
npm run build
```

`npm run build` runs `scripts/build-hooks.js`, which bundles these artifacts:

| Artifact | Output |
|----------|--------|
| Server, hook handlers, and the `hook` command | `plugin/scripts/server-service.cjs` |
| MCP server | `plugin/scripts/mcp-server.cjs` |
| Transcript watcher | `plugin/scripts/transcript-watcher.cjs` |
| `npx memsmith` CLI | `dist/npx-cli/index.js` |
| Viewer UI | `plugin/ui/viewer.html` |
| Dashboard UI (from `src/server/dashboard/ui.html`) | `plugin/ui/dashboard.html` |

The build fails if a required distribution file is missing or a bundle exceeds its size limit.

## Run your build locally

To test a change in Claude Code, build, copy the plugin to the installed marketplace location, and restart the server:

```bash
npm run build-and-sync
memsmith restart
```

`build-and-sync` builds the plugin, runs `sync-marketplace` to copy it to `~/.claude/plugins/marketplaces/shshalom/`, and runs `check:deploy` to detect drift between your build and the installed copy. Restart Claude Code to load changed hooks.

## Source layout

```text
src/
├── cli/            # Hook command, platform adapters, and hook handlers
├── npx-cli/        # npx memsmith commands (install, start, doctor, and others)
├── server/         # Server engine: routes, generation, retrieval, settings, auth
├── storage/        # Postgres access, schema, and migrations
├── servers/        # MCP server
├── services/       # Integrations, hooks runtime, telemetry, and shared services
├── sdk/            # Observation prompts and parser
├── ui/viewer/      # React viewer
└── shared/, utils/ # Shared helpers
```

## Test

```bash
bun test                      # Run the full suite
bun test tests/cli/handlers   # Run one directory or file
npm run typecheck             # Type-check the server and the viewer
```

CI runs the type check, the build, and `bun test` on every pull request. Some behavior, such as hook execution inside Claude Code, needs manual verification in a real session.

Write a test only when it pins behavior that a caller depends on or a bug that occurred. A new test must be able to fail against a plausible defect.

### Inspect a running server

```bash
memsmith status          # Server address, runtime, and dashboard URL
memsmith doctor          # Diagnose the install
tail -f ~/.memsmith/logs/memsmith-$(date +%Y-%m-%d).log
```

To log more detail, set `MEMSMITH_LOG_LEVEL` to `DEBUG` in `~/.memsmith/settings.json` and run `memsmith restart`.

To run a hook by hand, pipe its JSON input to the `hook` command. This example runs the Claude Code `context` handler:

```bash
echo '{"session_id":"test-123","cwd":"'$(pwd)'","source":"startup"}' \
  | bun plugin/scripts/server-service.cjs hook claude-code context
```

## Common changes

### Add a hook handler

1. Create the handler in `src/cli/handlers/`, and register it by name in `src/cli/handlers/index.ts`.
2. Add an entry that runs `hook claude-code <name>` to `plugin/hooks/hooks.json`. Copy an existing entry for the command wrapper.
3. Run `npm run lint:hook-io`. Handlers return a result and don't write to stdout or stderr directly.
4. Rebuild with `npm run build-and-sync`.

### Change the database schema

Schema definitions are in `src/storage/postgres/schema.ts`, and SQL migrations are in `src/storage/postgres/migrations/`. Add a migration, update the TypeScript types that read the table, and add a test under `tests/storage/`. Back up `~/.memsmith/pgdata` before you test a migration against your own data.

### Add an MCP tool

Define the tool in `src/servers/mcp-server.ts`, and add a test under `tests/servers/`.

### Change observation prompts

Edit the prompts in `src/sdk/prompts.ts` and the parser in `src/sdk/parser.ts`, and run `bun test tests/sdk`.

### Change the viewer

Edit the React components in `src/ui/viewer/`. Hot reload isn't available. Run `npm run build-and-sync` and `memsmith restart`, then refresh the dashboard address that `memsmith status` prints.

## Code style

- Use TypeScript strict mode, `async`/`await`, and explicit error handling.
- Follow the formatting of the surrounding code: 2-space indentation and single quotes.
- Write a comment only when the code can't state the reason, such as a constraint or an invariant.

## Release

Maintainers release with a version tag:

1. Update the version in `package.json` and the manifests that the build syncs, and add the release notes to `CHANGELOG.md`.
2. Run `npm run build`.
3. Commit, then push a `v<version>` tag.

The `Publish to npm` workflow checks that the tag matches `package.json` and publishes to npm through trusted publishing.

## Contribute

1. Fork the repository and create a branch.
2. Make the change and add tests.
3. Add user-facing changes to the `Unreleased` section of `CHANGELOG.md`.
4. Update the documentation in `docs/public/`.
5. Open a pull request that explains why the change is needed.
