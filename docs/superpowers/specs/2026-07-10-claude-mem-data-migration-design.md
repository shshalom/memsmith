# claude-mem → MemSmith data migration (this project) — Design

**What:** A one-off, idempotent, dry-run-first ETL script that copies the
`team-agent-memory` observations (2,372 rows) from the upstream **claude-mem** SQLite store
(`~/.claude-mem/claude-mem.db`) into the **MemSmith** Postgres store (dogfood DB on
:55432), transforming the flat worker shape into MemSmith's typed server shape so
MemSmith starts with this project's full decision/observation history.

**Why:** This Claude Code session runs upstream claude-mem, which holds the accumulated
decisions, conclusions, and reasoning ("whys") of the whole MemSmith engagement. Before
dogfooding MemSmith as the project's memory tool, migrate that history into MemSmith so
nothing is lost. Non-goal: switching the live plugin (separate, later decision) — this
just moves the DATA.

## Scope

**In:** `project='team-agent-memory'` observations (2,372) from SQLite → Postgres
`observations`, under a single team + project (the dogfood team
`d09ef94a-72cd-4a62-8eed-caa1eb52d32b`). Idempotent (re-runnable, no duplicates).
Dry-run mode. Count verification. Backup of the target DB before load.

**Out:** other projects (FormaFieldAgent, build-mobile, etc. — stay in claude-mem); the
live plugin switch; embeddings (`embedding_vec` stays empty — known gap, FTS covers
search); session_summaries / user_prompts tables (observations only).

## Source shape (verified)

SQLite `observations` (worker), for `team-agent-memory`:
- columns: `id, memory_session_id, project, text, type, title, subtitle, facts (JSON array
  string), narrative, concepts (JSON string), files_read, files_modified, prompt_number,
  discovery_tokens, created_at, created_at_epoch, content_hash, generated_by_model,
  agent_type, agent_id, metadata (TEXT/JSON or null)`.
- `type` distribution: discovery 1175, feature 477, change 371, bugfix 158, decision 113,
  refactor 78.
- `text`/`metadata` often null; `title`/`subtitle`/`facts` usually present.
- date range 2026-07-02 .. 2026-07-10.

## Target shape (verified)

Postgres `observations` (server): `id (text), project_id (text FK projects), team_id (text
FK teams), server_session_id (text, nullable), kind (text), content (text), content_search
(tsvector, auto), generation_key (text), metadata (jsonb), embedding (jsonb), obs_type
(text, NO enum constraint), lifecycle_state (text, CHECK in
open/active/blocked/deferred/resolved/superseded), supersedes (text FK, nullable), quality
(smallint 0-100 nullable), embedding_vec (vector, leave null), created_at, updated_at`.

FK: `team_id`→`teams(id)`, `project_id`→`projects(id)`. So a team row and a project row
must exist before insert.

## Transform mapping

| target column | source / rule |
|---|---|
| `id` | new deterministic id: `cmem-<source id>` (stable → idempotency) |
| `team_id` | the dogfood team UUID (constant) |
| `project_id` | a dedicated project row for team-agent-memory (created/looked-up by name) |
| `server_session_id` | null (no server session; source `memory_session_id` kept in metadata) |
| `kind` | `'observation'` |
| `obs_type` | source `type` verbatim (discovery/feature/change/bugfix/decision/refactor) — MemSmith treats these as known; no lossy remap |
| `lifecycle_state` | `'resolved'` for all (per schema.ts migration-002 rule for these types); `decision` → `'active'` (decisions stay live) |
| `content` | the richest available body: `text` if present, else `narrative`, else `title + subtitle` joined |
| `metadata` (jsonb) | pack the flat fields: `{ title, subtitle, facts: <parsed array>, narrative, concepts: <parsed>, files_read, files_modified, prompt_number, source: 'claude-mem-migration', source_id: <id>, memory_session_id, agent_type, agent_id, discovery_tokens }` |
| `quality` | null (unknown from source) |
| `supersedes` | null |
| `content_search` | auto-generated by the column default / trigger on insert |
| `embedding` / `embedding_vec` | null (known gap) |
| `created_at` / `updated_at` | from source `created_at` (ISO) / same |

`facts` and `concepts` are JSON strings in source — parse defensively (fall back to raw
string in an array on parse failure; never throw).

## Architecture

A single Node/Bun script `scripts/migrate-claude-mem.ts` (run with `bun`), NOT wired into
the app runtime:

1. **Connect** — open SQLite read-only (`~/.claude-mem/claude-mem.db`) + Postgres pool
   (`MEMSMITH_SERVER_DATABASE_URL` or the :55432 dogfood DSN).
2. **Ensure scope rows** — upsert the team row (dogfood team UUID) and a project row
   (`INSERT ... ON CONFLICT DO NOTHING`, id derived stably from the project name, e.g.
   `cmem-team-agent-memory`); print the resolved project_id.
3. **Extract** — `SELECT * FROM observations WHERE project='team-agent-memory'`.
4. **Transform** — per row, build the target record via the mapping above; parse JSON
   fields defensively.
5. **Load** — batched `INSERT ... ON CONFLICT (id) DO NOTHING` (idempotent via the stable
   `cmem-<id>` primary key). Batch size ~200.
6. **Modes** — `--dry-run` (default): transform everything, print counts + 3 sample
   transformed rows, insert NOTHING. `--execute`: actually load. `--project` overrides the
   source project name; `--limit N` caps rows (for testing).
7. **Verify** — after `--execute`, print target counts by `obs_type` and total, and a
   sample `content_search` FTS query to confirm search works.

## Safety

- **Backup first:** before `--execute`, dump the target `observations` table
  (`docker exec tam-test-pg pg_dump ... -t observations`) to a timestamped file; print the
  path. (Target currently has 1 row, so this is cheap and the rollback is trivial:
  `DELETE FROM observations WHERE id LIKE 'cmem-%'`.)
- **Idempotent:** stable `cmem-<id>` ids + `ON CONFLICT DO NOTHING` → re-runs insert only
  new rows; never duplicates.
- **Read-only source:** SQLite opened read-only; claude-mem's DB is never modified.
- **Never throws mid-batch:** a bad row is logged and skipped, not fatal (report skipped
  count at the end).
- **Scoped:** only `team-agent-memory` rows; the constant team UUID is the dogfood team
  (local only, never production — same rule as MEMSMITH_LOCAL_DEV_TEAM_ID).

## Error handling

- SQLite/Postgres connection failure → clear message, exit non-zero, no partial state.
- JSON parse failure on `facts`/`concepts`/`metadata` → fall back (raw-in-array / {}),
  count as a "soft" transform, continue.
- FK violation (team/project missing) → should be impossible after step 2; if it happens,
  abort with the offending row id.
- Lifecycle/obs_type: `obs_type` is unconstrained text (safe); `lifecycle_state` is
  CHECK-constrained — the mapping only ever emits `resolved`/`active`, both valid.

## Testing

- **Transform unit test** (pure, no DB): `tests/migration/transform.test.ts` — feed a
  representative source row (feature, with facts JSON array, null text) and assert the
  target record: `obs_type` preserved, `lifecycle_state='resolved'` (and `decision→active`),
  `content` falls back title+subtitle when text null, `metadata.facts` is a parsed array,
  `id='cmem-<id>'`, `source='claude-mem-migration'`. Also a malformed-facts row → no throw,
  raw string preserved.
- **Dry-run integration** (against :55432): `--dry-run --limit 5` prints 5 transformed rows
  and inserts nothing (target count unchanged).
- **Idempotency check** (manual/documented): running `--execute` twice yields the same
  target count.
- Verification query after load: `SELECT obs_type, count(*) ... GROUP BY obs_type` matches
  source distribution (2,372 total).

## Global constraints

- Script under `scripts/`, run via `bun`, NOT imported by the app runtime.
- New files start with `// SPDX-License-Identifier: Apache-2.0`.
- Source DB opened READ-ONLY; never mutate claude-mem's store.
- Idempotent + dry-run-first + backup-before-execute.
- Dogfood team UUID is local-only.
- Embeddings out of scope (FTS covers search).
